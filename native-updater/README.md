# 包内 Windows 更新助手 1.2.0

助手随插件 ZIP 一起提供：`uooc-helper/native-updater/UoocUpdater.exe`。从 2.3.0 起不再单独发布助手 ZIP，更新源继续固定为 GitHub 的 qiuxingya/uooc-helper。

## 安装或升级

1. 解压插件 ZIP，替换浏览器实际加载的原目录并重新加载扩展。
2. 在设置页“高级工具 → 版本与更新 → 安装或升级本机助手”点击“安装／升级本机助手”，保存并运行从包内取出的安装器。也可直接运行插件文件夹内上述 EXE。浏览器不能直接启动本机程序，首次运行及 Windows 提示需要用户自行确认。
3. 助手优先识别原有关联；首次使用时读取 Edge、Chrome 默认用户目录中的插件安装元数据，自动核对名称、ID、实际目录及扩展身份。只有多个副本时才需选择，不填写 ID 或地址。
4. 点击“关联并安装”或“升级助手并保留关联”。未检测到便携版、特殊浏览器目录时，可点“手动选择文件夹”，ID 自动计算；选择浏览器即可。
5. 回到设置页后，已有本机通信授权会自动检测连接；首次使用仍需点击“授权并连接本机助手”。确认连接后可开启自动安装，默认仍关闭。

不要关联源码仓库、浏览器 User Data 或商店安装目录。自动检测不修改浏览器 Preferences/Secure Preferences，不读取密码、Cookie、Key 或上传浏览器配置。元数据解析不支持、损坏或不可访问时保留人工文件夹选择，不扫描整块磁盘。

## 升级与关联保护

- 旧有效绑定保留，不要求重新填写；已失效的旧目录不会恢复。多个浏览器各自保持 Native Messaging 注册项。
- 安装至当前用户的 `%LOCALAPPDATA%\UoocHelperUpdater`，使用带版本和内容摘要的 EXE 文件名，避免覆盖正在运行的旧助手；不需要管理员权限，不设置开机服务，不删除旧 EXE。
- 只注册当前用户的 Edge/Chrome NativeMessagingHosts；allowed_origins 为验证后的精确扩展 ID，不使用通配符。
- 插件事务未结束时拒绝更换助手，请先在原插件完成确认或恢复更新。助手本身的新版本随插件包交付，仍由用户运行包内安装器完成切换，不由网页静默执行 EXE。

## 插件更新流程

插件和助手读取固定的最新正式 Release 的 `update.json`，不调用 GitHub REST API 日常查询。清单中的固定仓库地址、版本、大小和 SHA256 均校验。

只有全部课程页关闭后才覆盖原插件目录，保留下载暂存、权限变化拒绝、原路径更新、新版确认和失败回滚。不会改写学习进度或修改浏览器安全策略。

更新包只允许固定的 `native-updater/UoocUpdater.exe` 作为助手安装器，其他 EXE、脚本执行文件、越界路径和链接仍拒绝。包内 EXE 仅复制到插件目录，插件更新不会自动运行它。

旧 1.1.0 助手不支持含内置 EXE 的包。首次切换请手动升级插件并运行包内 1.2.0 助手，之后可继续自动更新兼容的插件版本。

## 卸载与开发

关闭自动安装会停止后续覆盖。再次运行安装器点击“解除已有绑定”，只移除本助手自己的浏览器注册，不删除插件及学习数据。

源码为 `UoocUpdater.cs`、`Discovery.cs`；运行 `build.ps1` 使用系统 .NET Framework 编译。完整插件构建见仓库 `tools/build-release.ps1`，仅生成插件 ZIP、update.json 和 SHA256SUMS.txt 三项发布附件。
